# branch
## 基本フォーマット
<種類>/<作業内容>

## 主な種類
* `feature/`(または`feat/`):新機能の追加
ex. 
    feature/user-profile
    feat/add-search-bar

* `fix/`(または`bugfix/`):バグ・不具合の修正
ex.
    fix/login-error
    bigfix/header-layout

* `refactor/`:リファクタリング（コードの整理）
ex.
    refactor/auth-logic

* `docs/`:ドキュメントやREADMEの修正
ex.
    docs/update-readme

* `chore/`:パッケージ更新や設定ファイルの変更など
ex.
    chore/update-packages

* `hotfix/`:本番環境で起きた緊急バグの修正
ex.
    hotfix/payment-crash


# commit
## 基本フォーマット
`<type>` (`<scope>`): <要約（30〜50文字以内）>　\
<変更した理由・背景・詳細（必要に応じて）> \
<関連Issue番号や破壊的変更など（必要に応じて）>  
```
fix: ログイン後に元のページへ戻らない問題を修正

ログイン画面へ遷移する際に、遷移元のURLを保持していなかったため、
ログイン後は常にトップページに戻っていた。
クエリパラメータ redirect_to に遷移元を保持し、ログイン後に戻すようにした。

Closes #123
```


## 主なtypeの種別
* `feat`:新機能の追加
* `fix`:バグ修正
* `docs`:ドキュメントの変更
* `style`:コードの意味に影響しない整形・フォーマット変更
* `refactoe`:機能追加やバグ修正を伴わないリファクタリング
* `test`:テストコードの追加・修正
* `chore`:ビルド設定や依存関係、雑務など

## 普段のコミット
変更の意図が1行で伝わる場合は、そのまま`-m`に要約だけを書く
git commit -m "fix: ログインボタンのレイアウト崩れを修正"

## 詳しい理由や背景も書きたいとき
    - `-m`を2つ並べる方法
    git commit -m "fix: タイムアウト時間を30秒に延長" -m "通信環境が不安定な環境でエラーが多発していたため"

    
    -`git commit`だけ打つ
    エディタが立ち上がるので、そこに複数行で書く

# PR
## タイトル
commitが1つの場合はコミットメッセージと同じで良い。
`type: 要約`の形。　　
ex. 
- 新機能：　　　　　　feat: ユーザー登録画面のバリデーションを追加
- バグ修正：　　　　　fix: スマホ表示でメニューが開かない不具合を修正
- リファクタリング：　refactor: API通信処理を共通関数に切り出し

## PR本文
### 概要（なぜこの変更が必要か）
- 〇〇の画面で△△のエラーが発生していたため修正しました。
- 関連Issue: #123

### 変更内容（何をしたか）
- 入力フォームの文字数制限を追加
- エラーメッセージの文言を修正

### 動作確認
- [ ] ローカル環境で正常に保存できることを確認
- [ ] 文字数オーバー時にエラーが表示されることを確認
